# 需求评审与 MVP 范围

MVP 范围：以用户图片为输入，可靠完成读取、灰度表示、基础运算、灰度变换和直方图均衡化，通过图像与统计证据复现，并仅保留每个实验最新一次个人运行结果。

本次为实际完成的技术自评。课堂小组互评尚需同学参与，未编造小组成员、签名或课堂意见。下表覆盖实验一需求文件中的全部编号；标签采用“必须”“推迟”“删除”。

| 原需求编号 | MVP 标签 | 评审结论 |
| --- | --- | --- |
| FR-01 | 必须 | 输入读取是全部处理入口 |
| FR-02 | 必须 | 记录尺寸、位深和通道，避免错误调用 |
| FR-03 | 必须 | 保留基线灰度接口；实验二按 uint8 范围执行 |
| FR-04 | 必须 | 保留明确的 Alpha 舍弃策略 |
| FR-05 | 必须 | 输出无损 PNG 并检查保存成功 |
| FR-06 | 必须 | 继续支持中文路径 |
| FR-07 | 必须 | 用户更换图片不改源码，路径配置化 |
| FR-08 | 必须 | 运行状态、属性和统计证据可复查 |
| NFR-01 | 推迟 | 保留实验一计时；实验二绘图与多图保存另报耗时，不套用单图≤2秒目标 |
| NFR-02 | 必须 | 独立环境与依赖版本可复现 |
| NFR-03 | 必须 | 模块化入口与文档能独立复现 |
| NFR-04 | 必须 | 原始输入哈希不变，清理只涉及实验结果 |
| NFR-05 | 必须 | 可解析状态和独立结果；按新要求改为每个实验仅留最新一次 |
| EX-01 | 必须 | 文件不存在时明确报错 |
| EX-02 | 必须 | 损坏与空输入不继续处理 |
| EX-03 | 必须 | 输出错误反馈，失败时保留此前完整结果 |
| EX-04 | 必须 | 实验二拒绝 uint16/float32，实验一仍保留 uint16 支持 |
| EX-05 | 必须 | 拒绝覆盖输入或冲突路径 |
| EX-06 | 必须 | 明确输出格式与必要参数 |

新增范围：实验二线性/固定伽马、加减乘除/混合、三类直方图、手写与 API 均衡化和差异统计均为“必须”；局部自适应伽马加分项与扩展位深为“推迟”；候选图形界面、复杂识别及相机参数恢复从本次候选范围中“删除”。上述候选项不是伪装成实验一既有需求的新编号。

技术评审意见：

1. 伽马参数与指数需明确区分，按 1/gamma 公式定义，并用已知像素核验亮度方向，避免引用指导书中矛盾的文字说明。
2. 原始 uint8 运算会回绕；线性和手写差值应先转浮点或有符号整数，不能只凭图像“看起来正常”验收。
3. 只拥有一幅个人插画时，应明确标记同图派生的偏暗、低对比度版本，不能把它们写成两张独立拍摄照片。
4. 手写均衡化需明确 CDF_min、舍入及恒定图策略，不能在分母为零时继续计算。
5. 最新结果替换先校验再清理旧目录；禁止清理输入和通过链接访问其他目录。不同实验独立保留各自的最新结果。
